Original Readme​

note

ModernLibs.FileHelpers​

Typed reading and writing of delimited (CSV, TSV, pipe, ...) and fixed-length text files for .NET 10, with a FileHelpers 3.x-style API.

You describe a record layout with attributes. A source generator, shipped inside the package, turns the layout into parsing and formatting code at compile time. There is no runtime reflection, so the library works with Native AOT and trimming.

ModernLibs.FileHelpers is an independent reimplementation modelled on the API of FileHelpers 3.x by Marcos Meli and contributors. FileHelpers 3.x is the reference for its behaviour. It is not the original project: please report problems with this library here, not upstream.

Install​
dotnet add package ModernLibs.FileHelpers

Requirements: .NET 10 (net10.0). Requires C# 11 or later (MLFH026): the .NET 10 SDK defaults to C# 14, so this only matters if your project pins an older <LangVersion>. The package has no runtime dependencies. The source generator is included as an analyzer; there is nothing else to install.

Quick start​

######### Delimited records

using ModernLibs.FileHelpers;

[DelimitedRecord(",")]
[IgnoreFirst(1)]
public sealed class Customer
{
    public int Id;

    [FieldQuoted]
    public string Name = "";

    public decimal Balance;

    [FieldConverter(ConverterKind.Date, "yyyy-MM-dd")]
    public DateTime Joined;
}
var engine = new FileHelperEngine<Customer>();

Customer[] customers = engine.ReadFile("customers.csv");   // the header line is kept in engine.HeaderText
foreach (Customer c in customers)
    Console.WriteLine($"{c.Id}: {c.Name} owes {c.Balance}");

engine.WriteFile("customers-copy.csv", customers);           // HeaderText is written back first

Fields are read in declaration order. Use [FieldOrder(n)] when you want the order to be explicit.

######### Fixed-length records

[FixedLengthRecord]
public sealed class Employee
{
    [FieldFixedLength(6)]
    [FieldAlign(AlignMode.Right, '0')]
    public int Id;

    [FieldFixedLength(20)]
    [FieldTrim(TrimMode.Right)]
    public string Name = "";

    [FieldFixedLength(10)]
    [FieldAlign(AlignMode.Right, '0')]
    public decimal Salary;
}
var engine = new FileHelperEngine<Employee>();

Employee[] staff = engine.ReadString(
    "000042John Smith          0001234.50\r\n" +
    "000043Mary Jones          0000980.00\r\n");

string text = engine.WriteString(staff);   // writes the same layout back

[FixedLengthRecord(FixedMode.AllowLessChars)] and the other FixedMode values control how lines that are shorter or longer than the layout are handled.

######### Record structs without per-record allocations

Records can be struct or record struct types. A struct whose fields are all value types (numbers, dates, bool, Guid, enums, ...) can be read through a callback or a streaming method without any heap allocation per record:

[DelimitedRecord(",")]
public record struct Trade
{
    public long Id;
    public decimal Price;
    public int Quantity;
}
var engine = new FileHelperEngine<Trade>();

decimal notional = 0;
int count = engine.ReadFile("trades.csv", trade => notional += trade.Price * trade.Quantity);

The callback overloads of ReadFile, ReadString and ReadSpan, and the streaming ReadSync, do not allocate a result array or a per-line string. A string field still allocates its string, and the array-returning overloads still allocate the array. ReadString and ReadSpan also accept a SpanRecordCallback<T> that receives each record by reference.

Features​
  • Delimited and fixed-length records described with FileHelpers-style attributes: [DelimitedRecord], [FixedLengthRecord], [FieldOrder], [FieldFixedLength], [FieldQuoted], [FieldTrim], [FieldAlign], [FieldConverter], [FieldNullValue], [FieldOptional], [FieldInNewLine], [FieldHidden], [FieldNotEmpty], [IgnoreFirst], [IgnoreLast], [IgnoreEmptyLines], [IgnoreCommentedLines], [ConditionalRecord] and more.
  • Record shapes: classes, structs, record and record struct types, including positional records, types without a parameterless constructor (values are bound by constructor parameter name) and required members. public, internal and protected internal fields and properties are mapped; use [FieldHidden] to leave one out. private and protected members cannot be mapped, and the ones FileHelpers 3.x would read as columns are reported (MLFH023, MLFH028).
  • Field types: string, char, bool, all integer types, decimal, double, float, DateTime, DateOnly, TimeOnly, DateTimeOffset, TimeSpan, Guid, enums and their nullable forms. Other types use a custom converter.
  • Converters: built-in converters with FileHelpers 3.x parsing rules and culture-independent defaults, per-field culture ([FieldConverter(..., CultureName = "de-DE")]), 3.x-style ConverterBase custom converters, and span-based ISpanConverter<T> converters.
  • Engines: FileHelperEngine<T> (read/write string, span, file, TextReader/TextWriter, append), FileHelperAsyncEngine<T> (record-by-record BeginRead*/ReadNext and BeginWrite*/WriteNext), MultiRecordEngine (several record types in one file) and MasterDetailEngine<TMaster, TDetail> (grouped master/detail lines).
  • Streaming: ReadSync (IEnumerable<T>), ReadAsync (IAsyncEnumerable<T> with cancellation), callback reads, and async variants of the multi-record and master/detail engines.
  • Parallel reads: ParallelReadFile / ParallelReadString extension methods split large inputs into chunks and keep sequential semantics (same records, errors and line numbers).
  • Events: BeforeReadRecord, AfterReadRecord, BeforeWriteRecord, AfterWriteRecord, Progress, and INotifyRead<T> / INotifyWrite<T> on the record type.
  • Errors: FileHelpers 3.x exception types and ErrorMode handling (see below).
  • Quoting as in FileHelpers 3.x: per-field quote character, QuoteMode on read and write, and multiline quoted values allowed by default.
  • Compile-time diagnostics: layout mistakes are reported as build errors and warnings (MLFH001-MLFH029), see the diagnostics reference. Diagnostics come from an analyzer shipped in the generator assembly. MLFH warnings can be suppressed as usual; errors that block the descriptor cannot (#pragma, .editorconfig, NoWarn are ignored). If they are hidden with [SuppressMessage] or RunAnalyzers=false, using the record throws a BadUsageException that names the errors (see suppressing diagnostics).
Error handling​

By default (ErrorMode.ThrowException) the first bad record stops the read with an exception that carries the line number:

ExceptionRaised when
ConvertExceptionA field value cannot be converted (also [FieldNotEmpty] violations). Has FieldName, FieldType, FieldStringValue, LineNumber, ColumnNumber.
NullValueNotFoundExceptionA non-nullable value-type field is empty and has no [FieldNullValue].
BadUsageExceptionThe line does not match the layout (extra fields, wrong fixed width, unclosed quote, ...).
FileHelpersExceptionBase class of all of the above; also raised for lines with too few fields.
try
{
    engine.ReadFile("customers.csv");
}
catch (ConvertException ex)
{
    Console.WriteLine($"Line {ex.LineNumber}, field {ex.FieldName}: '{ex.FieldStringValue}' is not a {ex.FieldType.Name}");
}

With ErrorMode.SaveAndContinue bad records are skipped and collected; ErrorMode.IgnoreAndContinue skips them silently:

var engine = new FileHelperEngine<Customer> \{ ErrorMode = ErrorMode.SaveAndContinue };
Customer[] good = engine.ReadFile("customers.csv");

foreach (ErrorInfo error in engine.ErrorManager.Errors)
    Console.WriteLine($"Line {error.LineNumber}, field {error.FieldName}: {error.ExceptionInfo?.Message}");
Streaming large files​
await foreach (Customer c in engine.ReadAsync("big.csv", cancellationToken))
{
    // one record at a time
}

using var reader = new FileHelperAsyncEngine<Customer>();
reader.BeginReadFile("big.csv");
while (reader.ReadNext() is \{ \} customer)
{
    // FileHelpers 3.x-style pull loop
}

See Opt-in features for callbacks, record recycling and parallel reads.

Native AOT and trimming​

All parsing and formatting code is generated at compile time. The library uses no reflection, Expression compilation or DynamicMethod, and is built with IsAotCompatible and IsTrimmable enabled, so the trim and AOT analyzers check it on every build. Applications that use it can publish with PublishAot=true.

Performance​

The read path works on ReadOnlySpan<char>: lines and fields are sliced, not copied, and numeric, date and other value-type fields are parsed straight from the span. Buffers are pooled. Struct records with value-type fields are read without per-record allocations (see above), and this is checked by the test suite.

The repository contains a BenchmarkDotNet suite that compares this library with FileHelpers 3.5.2, Sep, Sylvan.Data.Csv and CsvHelper. In the 4.8.0 results (Ryzen 9 5900X, WSL2, .NET 10, 100K rows):

  • Reading a 25-column delimited file into objects: 182 ms, against 344 ms for FileHelpers 3.5.2 and 352 ms for CsvHelper. Sylvan (107 ms) and Sep (122 ms) are faster, and allocate about 2.5 times less than ReadFile(path), which loads the whole file into a string (the streaming ReadFile(path, callback) overload allocates as little as Sep).
  • Reading a fixed-width file: 53 ms, against 84 ms for FileHelpers 3.5.2 (which allocates 16 % less).
  • Writing the same records to a string: 70 ms, against 75 ms for Sep and 173 ms for CsvHelper.

Results depend on hardware and record shape; see BENCHMARKS.md to run the suite on your own hardware.

Migrating from FileHelpers 3.x​

The API follows FileHelpers 3.x: the same attribute names, engine classes, events and exception types. Most code migrates by changing the namespace:

- using FileHelpers;
+ using ModernLibs.FileHelpers;

Some things are different. Runtime-reflection features (ClassBuilder, non-generic engines, DelimitedFileEngine options) are not available, a few signatures changed, and some defaults differ (UTF-8 encoding, \r\n line endings on every platform). The migration guide lists every difference we know of.

Versioning​

4.x is a ground-up modern reimplementation that follows FileHelpers 3.x, so its major version continues after 3.x. Versions 4.0.0 to 4.7.0 were development milestones, published only as source releases on GitHub. 4.8.0 is the first release on NuGet. From 4.8.0 on, the package follows Semantic Versioning. See the changelog.

#pragma warning disable CA2255 // ModuleInitializer in source-generated consumer code
#pragma warning disable CS0612, CS0618 // obsolete record members

namespace SerializerDemo;

file sealed class __PersonDescriptor : global::ModernLibs.FileHelpers.IRecyclableDescriptor<global::SerializerDemo.Person>
{
    public static readonly __PersonDescriptor Instance = new();

    private static class __Conv
    {
        internal static readonly global::ModernLibs.FileHelpers.Converters.DateTimeConverter __conv_field0 = new("yyyy-MM-dd", null);
    }

    private static int __Column(global::System.ReadOnlySpan<char> lines, global::System.ReadOnlySpan<char> value)
    {
        if (global::System.MemoryExtensions.Overlaps(lines, value, out int offset))
            return offset + 1;
        if (!value.IsEmpty)
            return -1;
        nint bytes = global::System.Runtime.CompilerServices.Unsafe.ByteOffset(
            ref global::System.Runtime.InteropServices.MemoryMarshal.GetReference(lines),
            ref global::System.Runtime.InteropServices.MemoryMarshal.GetReference(value));
        return bytes >= 0 && bytes <= (nint)lines.Length * sizeof(char) ? (int)(bytes / sizeof(char)) + 1 : -1;
    }

    private static global::ModernLibs.FileHelpers.ConvertException __ConvertError(global::System.ReadOnlySpan<char> lines, global::System.ReadOnlySpan<char> value, global::System.Type type, string field, string? extra, global::System.Exception? inner) =>
        new(new string(value), type, field, -1, __Column(lines, value), extra, inner);

    private static global::ModernLibs.FileHelpers.NullValueNotFoundException __NullValueNotFound(global::System.ReadOnlySpan<char> lines, global::System.ReadOnlySpan<char> value, string field) =>
        new(-1, __Column(lines, value), "No value found for the value type field: '" + field + "' Class: 'Person'. You must use the [FieldNullValue] attribute because this is a value type and can't be null or use a Nullable Type instead of the current type.");

    private static void __WriteText(global::System.Buffers.IBufferWriter<char> writer, global::System.ReadOnlySpan<char> text)
    {
        if (text.IsEmpty) return;
        text.CopyTo(writer.GetSpan(text.Length));
        writer.Advance(text.Length);
    }

    private static void __WriteQuoted(global::System.Buffers.IBufferWriter<char> writer, global::System.ReadOnlySpan<char> text, char quote)
    {
        // Indexed loops: foreach over a span needs C# 13 against .NET 10, whose span enumerator implements interfaces.
        int count = global::System.MemoryExtensions.Count(text, quote);
        int total = text.Length + count + 2;
        var dest = writer.GetSpan(total);
        dest[0] = quote;
        int pos = 1;
        for (int i = 0; i < text.Length; i++)
        {
            char c = text[i];
            dest[pos++] = c;
            if (c == quote) dest[pos++] = quote;
        }
        dest[pos] = quote;
        writer.Advance(total);
    }

    private static void __WriteQuotedField(global::System.Buffers.IBufferWriter<char> writer, global::System.ReadOnlySpan<char> text, char quote, bool always, bool multilineWrite, string separator, string field)
    {
        bool newLine = global::System.MemoryExtensions.IndexOfAny(text, '\r', '\n') >= 0;
        if (newLine && !multilineWrite)
            throw new global::ModernLibs.FileHelpers.BadUsageException("One value for the field " + field + " has a new line inside. To allow this value to be written you must add a FieldQuoted attribute with the multiline option set.");
        if (always || newLine || global::System.MemoryExtensions.IndexOf(text, separator, global::System.StringComparison.Ordinal) >= 0)
            __WriteQuoted(writer, text, quote);
        else
